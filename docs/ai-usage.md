# AI 활용

VocaRunner는 AI를 팀원으로 두고 개발했습니다. 이 문서는 README [AI 활용](../README.md#ai-활용)의 상세판으로, 역할 분담과 검증 방식, AI 판단을 바로잡은 사례를 정리합니다.

## 요약

- **역할**: 개발자가 기획 · 설계 · 결정을 맡고, 성격이 다른 AI 2개가 작업을 나눠 맡음
  - Claude Code: PC에서 파일 · 터미널 · 브라우저를 직접 다루는 개발 도구 → 주로 구현 · 테스트
  - claude.ai: 채팅 앱. IDE 연결로 같은 작업 폴더를 읽고 수정 → 주로 검토 · 문서 작성
- **검증**: 만든 AI와 검증하는 AI를 분리하고, 결과물의 주장을 코드 · DB · 실행 결과와 대조
- **사례**: 개발자가 바로잡은 AI 판단 6건, AI 사이 교차 검증으로 잡은 오류 4건, AI가 먼저 찾아낸 문제 4건

## 1. 역할 분담

- **개발자**
  - 서비스 기획 · 설계 방향 · 기술 도입 결정 (예: 월 비용 상한 아래 최소 구성, 로그인 미도입, 헥사고날 구조 전환)
  - 단어 데이터 기준 수립, 판단이 어려운 뜻 · 묶음의 결정
  - AI 제안의 채택 · 수정 · 거절
  - 저장소에 남는 변경의 승인: 커밋 · push는 개발자의 지시 후에만 수행, 병합은 개발자가 직접
- **Claude Code** (주로 작업)
  - 구현 · 리팩토링 · 자동 테스트 작성
  - 브라우저 테스트: Playwright MCP로 휴대폰 크기 화면을 직접 조작해 시험 전 과정을 수행하고 화면 · 요청 · DB 상태 확인 (300회 이상)
  - 단어 데이터 검사: 회차마다 출제된 문항 전체 검토, 임베딩 후보 추출 · 판정
- **claude.ai** (주로 검토)
  - 설계 검토 · 교차 검증 · 문서 작성 · 배포 절차 안내
- 작업에 따라 역할을 바꿈
  - 예: 문서는 claude.ai가 작성하고 Claude Code가 검증

## 2. 작업과 검증의 분리

- **원칙**: 만든 쪽과 확인하는 쪽을 서로 다른 AI로 분리
- **검증 방식**: 결과물의 주장을 원본(코드 · DB · 커밋 · 실행 결과 · 렌더링 화면)과 대조
  - 요약이나 기억으로 판단하지 않음
  - 수치는 측정 조건과 함께 확인
- **PR 리뷰 절차**
  1. 작업 쪽이 PR 생성 (본문: 무엇을 · 왜 · 확인한 방법)
  2. 검증 쪽이 리뷰 코멘트 작성 — 첫 줄에 결론(`병합 가능` 또는 `수정 필요`)
  3. 수정 커밋과 답글 → 재리뷰
  4. 병합은 개발자
  - 예: [용어 사전 PR](https://github.com/ruscayn/voca-runner/pull/2)
    - 리뷰에서 GitHub 렌더링 시 범위 표기(`A1~B2`)가 취소선으로 표시되는 문제 발견
    - 범위 표기를 띄어 쓰기로 통일한 뒤 재리뷰를 거쳐 병합
- **두 AI 사이의 소통**: 공유 문서에 작업 내용 · 검증 요청 · 검증 결과를 기록하고, 개발자가 확인 후 다음 작업을 지시

## 3. 기록과 규칙

- **기록** (저장소 밖, 비공개)
  - 결정: 누가 무엇을 정했는지 — AI 제안과 개발자 결정을 구분
  - 정정: 틀린 주장과 그 원인
  - 교훈: 같은 실수를 막기 위한 작업 규칙
- **작업 규칙 문서**: AI가 작업 전에 읽는 원칙
  - 예: 숫자 · 사실은 원본과 대조한 뒤 기록, 결정은 개발자, 커밋 · push는 지시 후
- **판단 결과를 문서와 빌드로 고정**
  - 용어 사전 → 코드 · 화면 · 문서의 이름 ([용어 사전](glossary.md))
  - 코드 규칙 → Checkstyle (위반 시 빌드 실패)
  - 계층 의존 방향 → ArchUnit 구조 검사 (위반 시 빌드 실패)

## 4. AI 판단을 바로잡은 사례

### 4-1. 개발자가 바로잡은 사례

| 상황 | AI 제안 | 판단 |
|---|---|---|
| 단어 출제 목록 적재 구조 설계 | 적재 서비스가 메모리 보관용 객체를 생성해 반환 | 서비스가 저장 방식까지 알게 됨 → 보관 방식은 인프라의 책임으로 두고, 서비스는 적재할 데이터만 전달 (관심사 분리) |
| 릴리스 절차 설계 — dev → main PR이 열린 동안 dev에 병합된 변경이 배포에 섞일 수 있음 | 릴리스 PR이 열린 동안 dev 병합을 멈추는 팀 규칙 | 규칙은 실수로 어겨질 수 있음 → 릴리스 브랜치를 항상 만들어 배포 시점을 구조적으로 고정 |
| 운영 DB 계정 비밀번호 설정 | 비밀번호를 임시 파일로 옮겨 설정하는 절차 | Parameter Store에 바로 저장하고 애플리케이션이 읽도록 변경 → 수작업 단계와 파일 노출 제거 |
| 원본 데이터에서 dig가 A1 명사 · B1 동사로 되어 있어 A1 보기가 어색함 | 레벨 · 품사를 맞바꾸거나, 원본에 없는 'A1 동사' 항목을 추가 | 출처 데이터(CEFR 레벨 · 품사)는 임의로 변경하지 않음 → 안 철회 |
| 한국어 뜻 검토 | 기억에 의존해 '그대로 둬도 된다'고 판단한 뜻 4개 | 실제 사전과 달라 사전 화면으로 확인해 수정 → 사전 확인이 필요한 항목은 '확인 필요'로 표시하도록 규칙화 |
| README 사례 작성 | 1회 수동 배포 절차를 '호환 배포'로 표현 | 과장 표현을 삭제하고 사례 이름 변경 ([문제 해결 사례 8](troubleshooting.md#8-db-변경을-배포-앞뒤로-나눈-배포-순서)) |

### 4-2. AI 사이의 교차 검증으로 잡은 사례

- README 초안의 사실 오류 3개 (코드 동작 · JUnit 버전 · 결함 수)
  - 원인: 코드 · 건수를 확인하지 않고 기록 요약으로 작성
- 혼동 단어 탐지 성능을 모델 순위 기준(알려진 21쌍 중 20쌍 상위)으로 기재
  - 실제 절차(후보 추출 → 판정 → 결정) 기준은 21쌍 중 15쌍 탐지 → 정정
- 임베딩 모델 문제의 원인을 '확인됨'으로 기재
  - 실제로는 발생 조건만 확인, 근본 원인은 미확정 → 정정
- 용어 사전 초안의 코드 이름 6개가 리팩토링 후의 실제 소스와 다름
  - 소스 대조로 정정 후 공개

### 4-3. AI가 먼저 찾아낸 문제

- WAF 본문 크기 제한이 500문항 제출을 차단한다는 점을 배포 전 계산으로 발견 ([사례 6](troubleshooting.md#6-waf-본문-크기-제한의-사전-발견))
- 공용 IP 환경에서 시작이 거절되는 문제를 서비스 공개 전 코드 검토로 도출 ([사례 4](troubleshooting.md#4-공용-ip-환경의-시작-차단-해소))
- 동시 요청으로 시작 상한을 우회하거나 제출이 500으로 응답하는 문제를 의도적인 동시 요청으로 발견 ([사례 1](troubleshooting.md#1-동일-시험의-동시-제출-처리) · [사례 2](troubleshooting.md#2-동시-시작-요청의-상한-우회-차단))
- 응답 유실 후 재제출이 실패하는 문제를 개발자의 질문에 답하며 코드를 검토하던 중 발견 ([사례 1](troubleshooting.md#1-동일-시험의-동시-제출-처리))

## 5. 반복된 오류 유형과 대응

| 유형 | 예 | 대응 |
|---|---|---|
| 확인 없는 단정 | 존재하지 않는 CLI 옵션으로 백업 스크립트를 작성해 첫 실행 실패 / 사전 뜻을 기억으로 판단 | 공식 문서 · 원본으로 확인 후 기록, 불확실하면 '확인 필요'로 표시 |
| 측정 조건 혼동 | 모델 순위 수치를 최종 탐지율처럼 기재 | 수치마다 측정 조건을 함께 기재 |
| 표현 과장 | 드문 결함을 '가장 심각'으로, 1회 수동 절차를 '호환 배포'로 표현 | 다른 AI · 개발자의 검토에서 근거와 대조 |
| 한쪽만 확인 | 메서드 목록만 보고 호출처를 확인하지 않음 / 의존 방향을 한쪽만 확인 | 사용처와 반대 방향까지 확인 |
| 지난 결정 누락 | 이미 결정한 사항을 다시 제안 | 제안 전에 결정 기록을 먼저 확인 |

## 6. 한계

- 브라우저 테스트는 AI가 회차마다 직접 수행하므로 스크립트로 남지 않아 CI에서 재실행할 수 없음
- 검증 쪽 AI도 같은 계열의 모델이라 같은 맹점을 공유할 수 있음 → 최종 결정과 원본 확인은 개발자가 수행
- 기록과 작업 규칙은 비공개 문서이므로 이 문서에는 요약만 공개
